## 🛠 Базовый шаблон (`_template.sh`)

```bash
#!/usr/bin/env bash
set -euo pipefail # Падать при любой ошибке, пустой переменной или сбое в пайпе |

main() {
    echo "Скрипт запущен"
}

main "\$@"
```

## 📚 Темы и мини-шпаргалка

### 1. Аргументы (`$1`, `$@`, `$#`)
* `$0` — имя самого скрипта.
* `$1`, `$2` — первый и второй аргументы.
* `$@` — все переданные аргументы.
* `$#` — количество аргументов.

```bash
ENV="\${1:-dev}"                                      # Если \$1 пуст, будет "dev"
TARGET="\${2:?Ошибка: укажите целевой хост вторым аргументом}"
```
> 💡 **Совет:** Всегда бери `"$@"` в двойные кавычки, иначе аргументы с пробелами внутри развалятся на
несколько отдельных кусков.
____________________________________________________________________________________________________________
### 2. Условия (`[[ ... ]]`)
```bash
if [[ -f "/etc/nginx/nginx.conf" ]]; then
    echo "Файл существует"
elif [[ "\(ENV" == "prod" && -n "\)TARGET" ]]; then
    echo "Прод-окружение, цель задана"
else
    echo "Что-то пошло не так"
fi
```
*Частые флаги: `-f` (файл есть), `-d` (папка есть), `-z` (строка пустая), `-n` (строка не пустая).*
> 💡 **Совет:** Всегда используй двойные скобки `[[ ]]` вместо одинарных `[ ]` — в них работают `&&`, `||`, регулярки `=~` и скрипт не упадет, если переменная окажется пустой без кавычек.
____________________________________________________________________________________________________________
### 3. Циклы (`for`, `while`)
```bash
# Перебор файлов
for file in /var/log/*.log; do
    echo "Обработка \$file"
done

# Безопасное построчное чтение файла
while IFS= read -r line; do
    echo "Строка: \$line"
done < servers.txt
```
> 💡 **Совет:** Никогда не пиши `for line in $(cat file.txt)` — это разобьет строки по пробелам. Для чтения файлов строка за строкой используй только `while IFS= read -r line`.
____________________________________________________________________________________________________________
### 4. Функции
```bash
check_service() {
    local service_name="\$1"
    systemctl is-active --quiet "\$service_name"
}

if check_service "docker"; then
    echo "Docker работает"
fi
```
> 💡 **Совет:** Всегда объявляй переменные внутри функции через `local`. Без этого слова любая переменная в Bash становится глобальной и может случайно перезаписать переменную с таким же именем в основном коде.
____________________________________________________________________________________________________________
### 5. Парсинг флагов (`getopts`)
```bash
VERBOSE=false
FILE=""

while getopts "vf:" opt; do
    case "\$opt" in
        v) VERBOSE=true ;;
        f) FILE="\$OPTARG" ;;
        *) echo "Использование: \$0 [-v] [-f файл]" >&2; exit 1 ;;
    esac
done
shift \$((OPTIND - 1)) # Сдвигаем аргументы, чтобы \$1 снова указывал на позиционный аргумент
```
> 💡 **Совет:** Не забудь `shift $((OPTIND - 1))` после цикла — без него скрипт не сможет нормально прочитать обычные аргументы, которые передали после флагов (например, `./script.sh -v prod`).
____________________________________________________________________________________________________________
### 6. Системное логирование (`logger`)
```bash
# Пишем в syslog с тегом my-backup-script
logger -t "my-backup-script" "Бэкап базы данных успешно завершен"

# Проверить потом можно через: journalctl -t my-backup-script
```
> 💡 **Совет:** Используй флаг `-s` (`logger -s -t ...`), если хочешь, чтобы сообщение одновременно писалось и в системный журнал, и в консоль (`STDERR`) при ручном запуске.
____________________________________________________________________________________________________________
### 7. Перехват сигналов и уборка (`trap`)
```bash
TMP_FILE=\$(mktemp)
trap 'rm -f "\$TMP_FILE"' EXIT INT TERM # Ставим сразу после создания файла!
```
> 💡 **Совет:** Всегда ставь `trap` **сразу следующей строкой** после создания временного файла или папки (`mktemp`). Тогда между созданием ресурса и назначением обработчика скрипту просто негде упасть и оставить мусор. И используй одинарные кавычки `'...'`, чтобы переменная раскрылась в момент срабатывания, а не заранее.
____________________________________________________________________________________________________________
### 8. Защита от повторного запуска (`flock`)
```bash
exec 200>/var/lock/my_script.lock
flock -n 200 || { echo "Скрипт уже запущен!"; exit 1; }

# Дальше идет основной код — блокировка снимется сама при выходе
```
> 💡 **Совет:** Оборачивай в `flock` через файловый дескриптор (`exec 200>...`), а не через запуск подкоманды. Так блокировка автоматически снимется ядром Linux, даже если скрипт убьют через `kill -9`.
____________________________________________________________________________________________________________
### 9. Ограничение времени работы (`timeout`)
```bash
# Ждать максимум 10 секунд; если зависло — отправить SIGKILL через 5 сек
timeout -k 5 10s curl -s https://example.com
```
> 💡 **Совет:** Всегда добавляй флаг `-k 5` (kill-after). Некоторые зависшие программы игнорируют мягкий сигнал завершения (`SIGTERM`), и без `-k` команда `timeout` всё равно будет висеть вечно.
____________________________________________________________________________________________________________
### 10. Планировщик (`cron`)
```cron
# Запуск каждый день в 03:30. Всегда указываем полный путь и перенаправляем вывод!
30 3 * * * /opt/scripts/backup.sh >> /var/log/backup.log 2>&1
```
> 💡 **Совет:** У `cron` сильно урезана переменная `PATH` (часто там только `/usr/bin:/bin`). Если в твоем скрипте вызывается утилита из `/usr/local/bin` (например, `docker-compose` или `aws`), она сработает вручную, но упадет в `cron` с ошибкой `command not found` — всегда прописывай `PATH` в начале скрипта.
Используйте код с осторожностью.
